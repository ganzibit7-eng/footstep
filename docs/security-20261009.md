# 보안 강화 · 2026-10-09

- 사용자 입력 ID를 HTML 속성과 JavaScript 문자열 두 단계로 인코딩. 외부 스크립트 출처 CSP, 객체 삽입 금지, base/form 제한, SDK 버전 고정.
- courses/bins/facilities 일반 회원 INSERT는 서버에서 pending으로 강제. 승인된 내용 수정 시 재검수, 소유자·식별자 변경 불가. 미승인 자료는 작성자/관리자에게만 조회.
- 알림은 리뷰/도움 활동의 DB 트리거로 생성. 클라이언트 직접 메시지 INSERT 거절.
- 계정 삭제는 getUser 서명 검증 후 session_id와 auth.sessions를 대조. 종료된 세션 및 세션 생성 15분 초과 거절. 4KB JSON 본문 제한.
- 보안 기록은 private.security_events. 읽기는 관리자 RLS, 쓰기는 서비스 역할 전용. 서버 처리 결과와 비검증 브라우저 보고를 분리. 원본 IP/이메일/비밀번호/토큰/쿼리를 저장하지 않음. IP 헤더 상관값은 HMAC 처리하며 신원 확인으로 간주하지 않음.
- 주체별 분당 10건, 출처별 하루 저장 상한 적용. 30일 기준 일일 정리 작업. 관리자 기간 필터·새로고침·최신 100건.

## 검증

실제 DB 롤백 테스트: approved INSERT가 pending으로 변경, 승인된 자료 수정 후 pending, 일반 회원 보안 요약 거절, 임의 알림 INSERT 거절, 비로그인 미승인 자료 조회 불가. 생성한 테스트 회원/코스는 모두 롤백.
관리자 역할 요약 조회 성공, 일반 클라이언트 감사 쓰기 권한 없음. 계정 삭제 테스트는 Auth/Storage 모형을 사용해 실제 계정을 삭제하지 않음.

## 범위

브라우저에서 발생한 인증 실패·정책 차단, 제출 상태 정규화, 계정 삭제 API의 처리 결과를 수집한다. 브라우저 보고는 공격 증거가 아니며 로그인 실패는 연결 오류일 수 있다. 정적 파일 404, 페이지 실행 전 요청, 전체 Supabase 인증/API 로그와 DDoS는 포함하지 않는다. 전체 경계 보호는 호스팅/WAF 로그 연동이 별도로 필요하다.
CSP는 현재 인라인 UI 코드 호환 때문에 unsafe-inline을 유지한다. 이 정책만으로 XSS가 모두 차단된다고 주장하지 않는다.
보안 Advisor의 의도적 집계/통계/포인트 SECURITY DEFINER 경고는 권한과 본문 검토 후 유지. private 내부 작업 테이블의 정책 없음은 기본 차단 목적. 유출 비밀번호 보호 설정 경고는 남아 있으며 현재 사이트 로그인은 이메일 링크·OAuth 방식이다.
