# 사진 저장소 분리 준비 — 2026-10-18

## 현재 적용

`_config.yml`에서 조사 자료, 개발 도구, SQL 원본, 중복 구형 홈 문서를 배포 대상에서 제외한다. GitHub 원본과 변경 이력은 보존한다. 실제 서비스 페이지, 사진, 약관·공지 보관함, 관리자 기능, 로그인·GPS 파일은 유지한다.

`node scripts/audit-pages-storage.mjs`는 제외 경로로 향하는 서비스 링크와 필수 파일을 확인하고 공개 원본이 975 MB를 넘으면 실패한다. 원본 합계, Jekyll 생성 결과, 압축된 배포 파일 크기는 서로 다르다. 이 검사를 SEO 자동 갱신에도 연결했다.

## 별도 사진 저장소: 원본 검증 및 읽기 통로 연결 완료

운영자가 R2 활성화·결제수단 등록을 직접 완료했고, 사진 전용 저장소와 공식 도구의 임시 권한을 승인했다. 원본 2,417개(783,399,692바이트)를 업로드하고 전체 SHA-256·크기·형식을 검증했다. 공개 주소·차단 검사는 `docs/photo-storage-20261018/verification.json`에 기록했다.

현재 방식은 비공개 Cloudflare R2 Standard 저장소와 Workers Free의 읽기 전용 사진 통로다. DNS를 변경하지 않고 `https://balzaguk-place-photos.balzaguk-photo-delivery.workers.dev`로 제공한다. r2.dev 및 저장소 직접 공개는 사용하지 않는다. 2026-10-18 공식 안내에서 월 10 GB-month 저장, 100만 Class A 요청, 1,000만 Class B 요청의 무료 제공량을 확인했다. 무료 제공량 초과 사용은 유료이므로 영구 무료로 안내하지 않는다.

- 요금: https://developers.cloudflare.com/r2/pricing/
- 가입·시작: https://developers.cloudflare.com/r2/get-started/
- 운영용 공개 도메인: https://developers.cloudflare.com/r2/buckets/public-buckets/

## 이전 절차

1. 운영자 계정에서 R2 사용과 청구 조건을 확인한다. 결제수단·유료 사용 승인이 필요한 단계는 운영자가 직접 결정한다.
2. 공개 장소 사진만 담는 별도 저장소와 `사진 전용 호스트명`을 연결한다. 회원·산책 좌표·DB 백업은 옮기지 않는다. r2.dev 개발용 주소를 운영 기본값으로 사용하지 않는다.
3. `node scripts/prepare-photo-storage.mjs <저장소 밖의 목록 파일 경로>`로 원본 SHA-256·출처·저작자·이용 조건·장소 연결을 보존한 전송 목록을 생성한다. 이 명령은 업로드·삭제·사이트 수정 없이 파일을 검증한다.
4. 제한된 저장소 쓰기 권한으로 업로드한 뒤, 공개 URL을 통해 전체 파일의 해시와 MIME 형식·크기를 대조한다. 공개 사이트에 쓰기 키를 넣지 않는다.
5. 검증된 호스트만 사진·상세 페이지·검색 자료에 반영하고 외부 이미지 요청 관련 개인정보 안내를 검토한다. 출처·이용 조건은 계속 표시한다.
6. 대표·추가 사진과 모바일 화면, 기존 주소, 찜·지도 연결을 확인한 뒤 별도 저장소에 복구 가능한 사본이 있는 사진만 Pages 배포에서 제외한다. 확인 전에는 현재 원본을 삭제하지 않는다.

별도 이전을 끝내면 현재 장소 사진 약 783 MB가 Pages 배포에서 빠질 수 있다. 실제 절감량은 이전 후 다시 계산한다.

## 무료 사용량 보호 범위

- Workers Free의 계정 합계 일 100,000 요청 상한을 유지한다. 코드상 요청당 R2 조회는 최대 1회여서 32일에 최대 320만 조회다. 무료 1,000만 회 안에 여유를 남긴다. 실제 요청 10만 회를 발생시키는 부하 시험은 하지 않았다.
- 사진 통로는 GET·HEAD만 받으며 목록·쓰기·알 수 없는 파일·쿼리·범위 요청을 저장소 조회 전에 거절한다. 원본 실패 시 재시도하지 않는다.
- 전용 업로드 도구는 전체 저장소 목록을 계산해 8GB·10,000파일 전에 거절한다. 월 작업 시도 횟수는 쓰기·목록 10,000회, 검증·조회 100,000회로 제한하고 SDK 자동 재시도를 끈다. 기록은 공개되지 않는 `.photo-storage-work/`에 저장한다.
- 위 제한은 현재 전용 통로·작업 도구의 범위다. 다른 키·수동 업로드·Workers 유료 전환·작업 기록 삭제 등은 제한을 우회할 수 있으며 계정 전체 0원 보장이 아니다.
- 처음 배포는 기본 `ENABLED=false`로 차단한다. 업로드·검증 및 무료 플랜 확인 뒤에만 `wrangler deploy --var ENABLED:true`로 활성화한다.
