발자국 사이트 보완 적용 안내 (2026-09-20)

[반영 순서]
1. GitHub 저장소의 index.html, sw.js, manifest.json, 아이콘 파일을 이 폴더의 파일로 교체합니다.
2. Supabase Dashboard > SQL Editor에서 database_sql/schema_v22_security_hardening.sql 전체를 실행합니다.
3. 배포 후 기존 서비스워커가 남아 있을 수 있으므로 브라우저를 한 번 새로고침합니다.
4. 카카오/Google 로그인은 각 공급자 콘솔과 Supabase Auth의 Redirect URL에 https://balzaguk.com 이 등록되어 있어야 합니다.

[이번에 해결한 문제]
- 산책 GPS 경로와 실시간 위치 원본이 공개 조회될 수 있던 정책
- 방문자 ID/유입경로/회원별 방문 정보와 포인트 내역의 공개 조회
- 비로그인 사용자의 사진·알림·도움돼요 데이터 쓰기
- 사용자 작성 문자열을 HTML로 바로 표시하던 저장형 XSS 위험
- 로그인 창을 버튼으로 닫을 수 없고 이메일 오류가 그대로 노출되던 문제
- 서비스워커가 외부 지도 타일·API 응답·사용자 사진까지 캐시하던 문제
- 존재하지 않는 og-image.png를 참조해 공유 미리보기가 깨지던 문제

[중요]
- schema_v22_security_hardening.sql을 적용하지 않으면 DB 개인정보 보호 수정은 완료되지 않습니다.
- Supabase 공개키(publishable/anon key)가 HTML에 있는 것은 정상 구조입니다. 보안은 반드시 RLS 정책으로 강제해야 합니다.
- 포인트 지급/차감은 현재 브라우저 코드가 직접 DB에 기록하는 구조라 완전한 부정 사용 방지는 어렵습니다. 결제나 현금성 보상으로 확장하기 전에는 Supabase Edge Function 또는 보안 함수(RPC)로 옮기는 것을 권장합니다.
- 실제 소셜 로그인 완료 여부는 공급자 계정/Redirect 설정과 실제 계정 승인이 필요하므로 배포 후 각 방식으로 1회씩 최종 확인하세요.

[추가하면 좋은 기능 — 우선순위]
1. 관리자 신고 처리·포인트 지급을 Edge Function으로 이동
2. 회원 탈퇴 시 Auth 계정까지 서버에서 완전 삭제
3. 관리자만 보는 집계 RPC(방문자/실시간 접속자)로 원본 데이터 조회 최소화
4. 코스/시설 등록 시 주소·좌표·문자 길이 서버 검증
5. 오류 모니터링(Sentry 등), 이용 이벤트 분석, 데이터 백업/복원 절차
6. 1200x630 전용 공유 이미지, 앱 설치 안내, 검색엔진 구조화 데이터
