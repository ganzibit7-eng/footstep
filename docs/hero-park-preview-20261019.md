## 16컷을 그대로 사용할 수 없는 이유

스토리보드 전체가 1448×1086으로 한 장면은 약 360×270이다. 카메라, 강아지 크기, 다리 접지, 나비 위치가 장면마다 달라 연속 프레임이 아니다. 잔디에 가린 발끝과 두 강아지가 겹친 뒷면은 원본에 없으며 털 경계의 배경색도 이미 섞여 있다. 단순 배경 제거·프레임 반복·화면 이동으로는 해부학적으로 일관된 달리기와 회전을 복원할 수 없다.

사용자는 ‘완성도 우선: 리깅된 3D 모델 또는 투명 연속 프레임을 준비한 뒤 구현’을 선택했다. 임의의 CSS 변형이나 스토리보드 슬라이드쇼로 대체하지 않는다.

## 필요한 에셋 — 아래 두 방식 중 하나

### A. 리깅된 GLB 모델과 동작 클립

- 주황색 포메라니안과 흰색 말티즈 각각 독립 모델. 네 다리, 척추, 목, 귀, 꼬리에 리깅. 두 캐릭터의 크기와 털색·얼굴을 스토리보드에 맞춘다.
- 나비는 별도 모델 또는 투명 이미지+날갯짓 클립.
- 대기/나비 발견, 가속, 달리기, 좌우 선회, 교차, 점프 이륙/체공/착지, 감속/첫 자세 복귀 동작.
- 움직이는 털·귀·꼬리도 루프 안에서 주기적으로 연결. 임의의 랜덤 물리 상태로 루프 경계를 깨지 않는다.
- 지면 원점과 앞 방향, 크기 단위를 명시한다. 발 접지 이벤트와 점프 구간을 전달한다. 지면 그림자는 캐릭터와 분리해 합성할 수 있게 한다.
- 모바일용 LOD·텍스처 축소본을 함께 제공하고 실제 기기 GPU·메모리 검사 후 예산을 확정한다. ‘실사 털’의 성능은 실제 모델을 보고 판단한다.

### B. 동일 카메라의 투명 PNG 연속 프레임

- 원본 PNG RGBA 시퀀스, sRGB, straight alpha. 강아지 두 마리·나비·지면 그림자를 각각 별도 패스로 제공한다.
- 10~12초, 30fps 기준 300~360프레임을 예시 목표로 한다. 프레임 수는 중간 동작의 품질을 보고 조정하며 16장으로 제한하지 않는다.
- 각 캐릭터 프레임의 캔버스 크기·피벗·발 기준선이 동일해야 한다. 털과 꼬리 끝을 자르지 않고 8% 이상 여유를 둔다. 시작 크기는 캐릭터별 1024×1024를 권장하며 실제 표시 크기에 맞춰 최적화한다.
- 카메라는 고정한다. 배경, 잔디, 바닥색을 포함하지 않는다. 기존 배경의 우측 따뜻한 햇빛 방향과 맞추고 털 가장자리에 녹색 잔디 테두리가 남지 않게 한다.
- 동일 시간축의 위치(x/y/z), 방향, 점프 높이, 접지, 그림자 크기·불투명도 정보를 함께 제공하면 PC·모바일 안전 영역에 재배치하기 쉽다.
- 출고물은 편집 가능한 원본이다. 웹에는 원본 PNG 720장을 그대로 요청하지 않는다. 알파 품질·브라우저 호환성·용량을 검증해 아틀라스/압축 시퀀스 또는 투명 영상+폴백으로 변환한다.

## 루프와 동작 인계 기준

- 0초/마지막 시점의 위치·회전·자세가 일치(C0)하고 속도·진행 방향도 이어져야 한다(C1). 점프 중간이나 급회전 중간에 루프를 자르지 않는다.
- 예: 발견/대기 → 가속/추격 → 교차/선회 → 점프/착지 → 감속/원래 위치와 자세로 복귀.
- 두 강아지의 깊이 순서를 교차 시점마다 일관되게 처리하고 서로 관통하지 않게 한다. 각 캐릭터와 그림자·나비 패스의 시간축은 동일하다.
- 30fps에서 마지막 파일은 0초를 중복 저장하는 방식으로 멈춤을 만들지 않는다. 한 주기 뒤의 다음 샘플이 0초와 연결되는지 검증한다.
- 꼬리·귀·털·날개·그림자도 본체와 같은 루프 위상으로 복귀한다.

## 에셋 수령 후 구현·승인

정지 포스터를 먼저 표시하고 필요한 동작 에셋만 지연 로드한다. 화면 밖/백그라운드에서는 정지하고, prefers-reduced-motion에서는 포스터만 표시한다. 저사양 기기와 로드 실패도 정지 포스터로 대체한다. 실제 에셋이 준비되기 전에는 루프·털·발 접지·프레임 속도·메모리 성능을 완료로 표시하지 않는다.

PC 1440×1000, 아이폰 390×844, 갤럭시 360×800 및 412×915, 작은 PC 1024×768에서 배경 선택과 가로 넘침, 텍스트/날씨/캐릭터 영역 사이 간격을 검사한다. 이번 검사는 브라우저 화면 크기 시뮬레이션이며 실기기 Safari/Chrome GPU 검증을 대신하지 않는다.

새 에셋을 연결한 움직이는 미리보기와 변경 내용을 다시 제시하고 사용자 승인 후에만 main 반영·배포한다.

## 재생 기반 준비 — 동작 에셋 미연결

hero-park-player.js를 추가했다. 실제 에셋은 없으므로 미리보기에서는 모듈만 로드하고 생성·재생하지 않는다. 기존 배경/배치 미리보기와 운영 사이트는 그대로다.

- 세 캐릭터의 동일 프레임 번호를 하나의 시간축으로 계산한다. 동작과 회전 자체는 제작된 프레임에 포함되어야 한다.
- ready 상태, 루프·알파 검토 확인, 3개 독립 레이어, 프레임/좌표 개수, 디코딩 예상 메모리 64MiB를 검사한다.
- 같은 출처 /assets/hero-park/의 에셋만 읽으며 동시 로드는 4개로 제한한다.
- 전체 프레임 로드 실패 시 정지 포스터를 유지한다. 움직임 감소 설정에서는 애니메이션 다운로드를 시작하지 않는다.
- 화면 밖/백그라운드에서는 재생 시간을 멈추고 다시 들어오면 이어서 재생한다. 해제 시 디코딩 이미지와 관찰자를 정리한다.
- tests/hero-park-player.cjs에서 루프 인덱스, 준비 전 거부, 검토 누락, 메모리 한도, 정지 설정의 다운로드 0건, 오프스크린 일시정지, 자원 해제를 검증했다.

실제 에셋이 없으므로 시각적 루프 연속성, 털/귀/꼬리/발 접지, 실제 네트워크 용량과 기기 성능은 아직 검증되지 않았다. 공원 배경만 보이는 상태를 완성된 애니메이션으로 안내하지 않는다.

현재 사용 가능한 도구로 해당 이미지에서 완성도 높은 리깅 모델이나 일관된 수백 장의 투명 동작 프레임을 생성할 수 없다. 3D 제작 도구/제작자의 GLB 또는 투명 시퀀스 제작 결과를 받아야 다음 단계가 가능하다.

## 승인한 캐릭터 외형 적용

사용자가 확인한 포메라니안·말티즈 정지 시안을 미리보기 하단 잔디에 배치했다. 생성 원본은 outputs/hero-park-20261019/dog-pair-concept-v1.png에 보존했고 웹용 RGBA WebP는 assets/hero-park-preview/dog-pair-v1.webp(960×480, 156116바이트)이다. 원본의 실루엣·색·포즈를 바꾸지 않고 축소·압축했다. 제작 도구는 내장 image_gen이며 스토리보드의 품종·털색·표정을 참고했다. 생성된 투명도 범위는 0~255다.

투명 이미지는 고정 배경과 독립 레이어이고 그 아래 두 개의 약한 접지 그림자를 추가했다. 실제 연속 동작은 아니며 나비 추격·회전·점프·털 움직임을 구현했다고 표시하지 않는다.

PC 1440×1000에서 시각 확인. 모바일 360×800, 390×844, 412×915에서 가로 넘침 없음, 이미지 정상 로드, 전부 동작 예약 영역 안에 포함, 날씨 카드와 최소 64px 이상의 간격 확인. 모바일 전체 구성 사진은 390×1100으로 별도 캡처했으며 실제 화면 크기 검사는 위 세 규격으로 수행했다.

현재 변경은 로컬 preview 브랜치에만 있으며 운영 index.html·서비스워커와 main은 변경하지 않았고 push·배포하지 않았다.

## 16컷 동작 시안 (최신 상태)

승인한 외형을 참고해 내장 image_gen으로 품종별 4×4 투명 제자리 달리기 시트를 새로 생성했다. 기존 배경 포함 스토리보드를 잘라 재생하지 않았다. 생성 시트에서 발 기준선을 정렬한 192×192 RGBA WebP 16장씩을 추출했다. 총 32장 480,240바이트, 디코딩 약 4.5MiB다. 원본은 outputs/hero-park-20261019의 pom-trot-sheet-v1.png와 maltese-trot-sheet-v1.png에 보존했다.

preview 전용 어댑터가 초당 18프레임으로 반복하며 말티즈는 3프레임 위상을 달리한다. 나비는 별도 벡터 레이어이고 접지 그림자는 캔버스에서 그린다. 제자리 달리기 시안이며 실제 리깅, 회전·교차·큰 점프를 완성한 결과는 아니다. 생성 이미지의 미세한 형태 변화도 남아 있어 완벽한 자연스러움을 보증하지 않는다.

공유 시계, 전체 프레임 사전 로드, 동시 로드 4개 제한, 화면 밖·백그라운드 정지, 움직임 감소 설정의 정지 포스터와 애니메이션 요청 생략 검사가 통과했다. 캔버스는 크기가 바뀔 때만 재할당한다. 360×800·390×844·412×915에서 가로 넘침 없고 날씨와 동작 영역 사이 최소 54px를 확인했다. PC 1440×1000에서도 배치를 확인했고 지도 전환 시 재생 정지를 확인했다. 실기기 검사는 아니다.

현재도 로컬 미리보기만 변경했으며 운영 index.html·sw.js는 origin/main과 동일하다. 배포 승인 전 push하지 않는다.

## 동작 보정
16fps로 속도를 조절하고 생성 프레임에 중복되는 외부 점프 효과를 제거했다. 접지 그림자를 고정하고 위치 표본을 선형 보간해 30fps로 그린다. 이미지 자체를 교차 페이드하지 않아 겹친 다리 잔상을 추가하지 않는다. 반복 경계 위치 보간 검사와 기존 감소 설정·중지·정리 검사를 통과했고 모바일 화면 밖 정지 및 화면 진입 재생을 확인했다. 프레임 자체의 형태 변화는 남아 있으며 리깅 기반 회전·교차·점프는 미완료다. 운영 배포 없음.
