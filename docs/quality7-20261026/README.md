# 7차 UI/UX 품질 개선

2026-10-26 / 기준 `c64b16ce13`. 구현·로컬 검사 완료. GitHub/운영 결과는 배포 기록에 갱신한다.

## 유지한 부분

6차의 사진 프레임·허용된 크롭/원본 비율 규칙·장소별 바인딩·3개 이하 핵심 정보·CTA 정렬·카테고리별 상세 구조·출처 원문을 유지했다. 홈페이지 배경·강아지·섹션·사진 카드와 DB/Auth/GPS/회원/관리자/제휴 데이터는 변경하지 않았다. 새 모션·라이브러리를 추가하지 않았다.

## 실제 문제와 수정

1. `방문 전 문의추가 준비물 기준`처럼 제목/본문의 텍스트가 붙었다. 공통 상세에서 공백과 별도 본문 요소를 추가했다. 4,136개 안내 영역을 검사했다.
2. 사진 없는 전문업소도 3:2 빈 사진 프레임을 사용했다. 하위 페이지의 사진 없는 헤더만 약 89px로 줄이고 업종별 선 아이콘을 적용했다. 사진과 섞인 PC 행은 기존 subgrid로 제목·CTA 정렬을 유지한다. 사진이 있는 프레임은 변경하지 않았다.
3. 미용/약국/돌봄에도 ‘진료·이용 조건’이 반복됐다. 공통 업종 안내를 나누고 모든 정적 목록과 동적 전문업소 검색에 적용했다. 추측한 서비스 정보는 추가하지 않았다.
4. 확인된 전화 문의가 보조 메뉴에 숨겨져 있었다. 공개 자료에서 추출한 기존 전화 2,401곳을 주요 행동 영역에 배치했다. 전화번호나 마스킹 정보는 변경하지 않았다.
5. 다중 사진에서 제공기관의 역할/촬영자 미표기/원문 링크 문구가 반복됐다. 사진별 저작자와 라이선스 링크는 계속 보이고, 반복 역할 설명만 줄였다. 전체 원문·사진별 의무 고지는 기존 묶음에 보존했다.
6. 모바일 필터가 늦게 닫히고 빈 결과 자리 아래의 안내가 크게 밀렸다. 초기 요청의 필터 상태와 결과 공간을 데이터 파싱 전에 확보한다. 기본 무검색 화면에는 큰 빈 공간을 남기지 않으며 결과 없음·초기화 동작도 유지한다.
7. 검색마다 4,619개 레코드의 같은 문자열을 다시 결합·소문자화했다. 변경 감지가 있는 WeakMap 캐시를 사용한다. 정보가 바뀌면 다시 색인한다. 원문 조건 검색도 유지한다.
8. 검색 사진에 파일 해시·다운로드 크기·매칭용 ID·다른 코스 연결 목록이 중복 포함됐다. 내부 관리값 8,694개만 공개 검색 페이로드에서 제외했다. 출처/저작자/라이선스/원본 링크/비율/크롭 조건/사진 설명은 보존했다. 원천 파일과 상세 원문은 그대로다.
9. 상세 지도 링크가 `?facility=...`로 홈에 진입한 뒤 `#map`을 추가해 뒤로 가기에 중간 홈 단계가 생겼다. 기존 지도 경로를 처음부터 가리키도록 `#map`만 추가했다. 지도 라이브러리/좌표/GPS 로직은 바꾸지 않았다. 의도적으로 바뀐 링크 4,169개를 원문 보존 검사에서 별도로 집계했다.

## 전체 적용 / 자동 검사

- 상세 **22,317개**, 목록 **1,114개**, 추천이 있는 상세 **4,574개**, 카드 노출 **58,414회**. 기존 바인딩 검사 미적용 **0개**.
- 사진 없는 카드 **32,817회 노출**, 구분된 안내 4,136곳, 주요 전화 2,401곳 검사. 수치는 장소 수와 카드 중복 노출 수를 구분한다.
- 원문 107,561개 dt/dd 필드, 본문 사진 참조 5,639개, 상세 메타/JSON-LD, 목록 스키마/사이트맵·홈 지역 카드 마크업 비교 오류 0. 의도된 지도 링크의 fragment 수정 외 원문 출처 목적지는 유지했다.
- 검색 데이터 4,619개 전부의 이름/경로/분류/지역/주소·검색 정보/원문 조건/카드 사실 동일. 48가지 검색 조건의 전체 결과·순서 일치. 사진의 남아 있는 모든 공개 속성도 원본과 일치한다.
- 최종 로컬 **278/278 통과**. 기존 미추적 offline-shell 1개를 포함하며 추적 검사 예상 합계는 277개다. 해당 미추적 파일과 `supabase/.temp`는 커밋하지 않는다.

## 실제 브라우저 검증

- 요청한 7개 URL 및 사진 없는 캠핑장·숙소·병원·전문업소 목록·부분 GPX를 포함한 **12화면 × 7폭 = 84조합**(360/375/390/430/768/1024/1440).
- 가로 넘침, 붙은 문의 문구, 표시된 주요 CTA 44px 미달, 화면 안에서 로드 실패한 사진 0.
- 더보기 20→40, 다음 결과 포커스, 로컬 찜 true/false 및 성공 안내. 목록/상세/실제 운영 지도 이동 후 한 번에 상세 복귀. 캠핑/이름순/40개 결과 및 키보드 진입 전후 스크롤 **6828px → 6828px** 유지.
- 지도 마커는 실제 운영 화면의 ‘가야산오토캠핑장’ 버튼이 보이는 것을 확인했다. 전화·길찾기 URL은 확인했으나 실제 전화 발신·외부 앱 경로 안내는 실행하지 않았다.
- 기존 reduced-motion·키보드 포커스·사진 갤러리 회귀 검사는 유지했다. 실물 iPhone/Galaxy·실시간 GPS·로그인 후 계정 저장은 이번 환경에서 검증하지 않았다.

## 성능 측정

같은 로컬 브라우저 390px, 각 3회 탐색·10개 검색(전후 각 30표본). `performance-final-mobile.json` 참조. 실제 휴대폰 또는 운영 네트워크 속도 측정으로 해석하면 안 된다.

| 지표 | 이전 | 이후 |
|---|---:|---:|
| 탐색 HTML 원본 | 5,063,354 bytes | 4,681,082 bytes |
| 동일 Node gzip 설정 | 585,168 bytes | 427,717 bytes |
| 초기 CLS(3회 동일) | 0.129986 | 0.000303 |
| 48조건 순수 필터 CPU 중앙값 | 196.17ms | 24.23ms |
| 검색 클라이언트 JS | 12,102 bytes | 12,778 bytes |

HTML 약 7.5%, gzip 약 26.9% 감소. 순수 필터 CPU 결과는 DOM 렌더링을 포함한 사용자 체감 시간과 다르다. 브라우저 검색 이벤트 중앙값은 `performance-summary.json`에 별도로 기록했다. 로컬 DOM 준비 시간은 이전 161.5~314.5ms, 이후 162.0~194.3ms로 변동이 있어 일관된 초기 로딩 시간 단축은 입증하지 못했다. 사진 프레임을 예약해 이미지로 인한 화면 이동을 추가하지 않았고, 검색 결과를 줄이거나 데이터를 누락해 빠르게 만든 것이 아니다.

## 남은 한계

전체는 자동 검사이고 화면은 대표 검증이다. 모든 장소의 현장 정책/사진 촬영 시점/외부 원문을 재조사한 작업은 아니다. 원문 오타·미확인 조건은 추측하지 않고 보존했다. 물리적 휴대폰에서의 GPS·네이티브 공유/길찾기는 별도 확인이 필요하다.
