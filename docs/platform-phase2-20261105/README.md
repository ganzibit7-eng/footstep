## 실제 구현
- place-search.js: 이름/주소/코스명 띄어쓰기·중점·일반적인 문자 사이 하이픈·전각/분해 한글·일반 행정구역 표기를 검색한다. 숫자 주소12-3과123, 서로 다른 데이터 필드의 문자열 경계는 구분. 쿼리의 정규식 문자는 문자 그대로 안전하게 처리한다.
- 비용이 컸던 초기 전 필드 정규화 방식(첫 필터 약40ms)은 폐기했다. 원문 캐시+안전한 공백 허용 패턴과 확정 범주 선별 후 텍스트 검사를 사용한다. 새 라이브러리 없음.
- 검색어 관련성: 장소명 완전 일치→앞부분 일치→이름에 모든 단어→일부 이름 단어→기타 자료 순, 동률은 기존 순서. 평점/인기도/추천 점수를 생성·노출하지 않는다.
- 검색어가 있으면 최초 관련성 정렬, 사용자가 사진/이름/등록 순을 선택하면 유지. sort=photos도 공유URL에 보존하고 재방문 시 복원. 검색어가 없으면 관련성 옵션은 비활성화하고 사진 기본값 유지.
- 적용된 검색어/지역/종류/업종/동반조건 필터를 개별 버튼으로 해제. 없던 동반 정보를 조건 충족으로 취급하지 않는다.
- 빈 결과에서 검색어만 지우기/지역만 전체로/자료 필터 해제를 사용자가 선택한다. 다른 조건을 몰래 바꾸지 않는다. 전체 초기화도 유지한다.
- 검색 범위 안내: 이 화면은 코스·동반장소·편의시설. 전문업소는 기존 /pet-care/ 검색으로 안내. 총21,864장소가 이 검색에 모두 포함된 것처럼 표현하지 않는다.
- discovery-search.css는 discover에만 연결. 기존 카드·갤러리·메타데이터·홈 공통스타일은 수정하지 않는다.
- scripts/discovery-layout.mjs/공통 게시 함수의 검색 자산 버전 반영. 재실행 동일(idempotent). SW캐시 v238-search.

## 검증 결과
- 운영 이전: kind=courses&q=서울숲공원길 검색 결과0을 직접 확인. 로컬 이후1개(c31) 확인. 문구/행정명·NFKC·숫자 주소·필드 경계·정규식 안전·캐시 갱신 자동검사.
- 첫 전체384개 중2실패는 이전 자산 버전 assertion/구형 empty 상태 DOM 위치 가정. 새 자산 상수 및 실제 reset 버튼 대상으로 수정하고 개별 완화·명시 정렬 유지 회귀검사를 추가. 최종 전체386/386통과 (사용자 미추적 offline-shell1 포함).
- 실제 브라우저: 부산+서울숲 검색0 → 지역만 전체로 클릭 → 검색어·코스 종류 유지 및1결과. 검색어 chip만 제거 →412코스/20표시. 더 보기40·60 및 상세 왕복 후 query/kind/region/shown 보존.
- 스크롤 진단: 입력 전 읽은 y와 복귀 y가384px 달랐으나, 테스트 도구가 링크 포커스 시 스크롤을 옮긴 뒤 pagehide에서 저장한 값이 다르기 때문이었다. 임시 진단에서 실제 저장/적용 목표14194와 복귀14194 동일 확인. 정상 복귀 코드는 수정하지 않았다. 진단console과debug 자산 URL은 제거.
- 360/390/430/768/1024/1440px: 가로 넘침0, 제거 버튼44px, 고유 accessible name, 기존 결과 aria-live=polite 유지. 사진 순 선택 후 일반 reload에서도 sort=photos와 검색어 유지 확인.

- discover meta/canonical/JSON-LD 원본과 동일, 기존 index 홈 코드 동일, 생성기 두 번째 실행 변경0 확인. 전수 SEO 자동검사는 기존 회귀 세트를 사용하며 대표 화면 검사와 구분한다.
