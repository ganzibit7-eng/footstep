# 비회원 정보 정정 요청

기준 main `0b02c3701f81bcb3b735412f1bd111c01094275a`. 홈의 시각 디자인은 유지하고 상세 화면의 접수 버튼과 관리자 알림 이동만 추가했다.

## 구현 범위

- 공통 `scripts/correction-entry.mjs`와 최종 생성 후처리 `publish-control-polish.mjs`. 공개 상세 22,317개: 산책코스412, 장소4,169, 전문업소17,698, 편의시설38. 제목·주소 다음에 `정보 정정 요청`. 입력 대상은 해당 페이지 canonical에서 얻고 다른 장소의 데이터 속성을 복사하지 않는다.
- SPA 코스 상세에도 기존 공개 상세 URL이 있는 경우 같은 양식. 원본 장소·코스, SEO URL·사진 라이선스·로그인·GPS·찜·관리자 권한은 바꾸지 않았다.
- 요청 유형·10~2,000자 내용·선택 공개 HTTPS 자료 링크. 대상 이름과 URL 자동 연결. 회원 식별자·연락처를 요구하거나 계정 토큰을 전송하지 않는다. 접수 성공은 서버의 동일 접수번호 확인 후에만 표시한다. 실패 시 내용 유지, 재시도 시 같은 내용은 같은 접수번호, 내용 변경은 새 번호. 중복 클릭 차단과 닫기/포커스 복귀, 작은 화면 내부 스크롤 제공.
- 관리자 메뉴 `정정 요청`: 상태별 목록·페이지 이동·검토 메모·처리 상태·충돌 방지. 완료 또는 반영하지 않음은 사유 필수. 공개 정보는 자동 수정되지 않으며 기존 관리 절차에서 별도로 반영해야 한다.
- 기존 관리자 계정별 알림에 접수 제목과 유형을 기록한다. 자유 입력 내용은 알림에 넣지 않고 비공개 접수함에서 확인한다. 알림의 `정정 요청 확인`은 해당 관리자 메뉴로 연결한다. 외부 이메일·SMS·OS 푸시를 보내는 기능은 추가하지 않았다.

## 저장·권한·오남용 제한

전용 private 테이블3개와 RPC3개, Edge `content-correction` v1. Supabase migration `20261106113627_anonymous_content_corrections`. 기존 reports/notifications 정책은 변경하지 않았다.

Edge는 명시적으로 비회원 제출을 받되 허용 Origin·공개 앱 키·본문 크기·필드·공개 URL 경로를 검사한다. 고정된 발자국 호스트의 실제 공개 제목만 읽고, 제출자가 적은 외부 자료를 서버에서 가져오지 않는다. DB 접수 RPC는 서비스 역할 전용이며 관리자 RPC는 기존 `is_admin(auth.uid())`로 다시 검사한다. 일반 회원·비회원의 private 테이블 직접 접근은 차단한다.

일별 HMAC 네트워크 식별값만 제한표에 저장하고 원시 IP·로그인 계정과 연결하지 않는다. 3건/시간,10건/일(동일 식별값), 전체100건/일과 신규 테이블10MB 제한. 공용 네트워크 사용자는 한도를 공유할 수 있다. Origin·공개 키·허니팟은 신원 인증이나 완전한 봇 차단이 아니며 Edge 호출 자체의 요금 상한을 보장하지 않는다. 공개 API 호출량은 기존 공급자 운영 지표로 확인해야 한다.

접수180일 또는 완료·반영하지 않음 기록 후90일 중 빠른 기한, 제한표48시간 뒤 매시간 정리한다. 정정 알림은180일 뒤 정리한다. 해당 기능 처리 안내와 기존 방침의 변경 전 스냅샷을 제공한다.

## 검증 기록

- SQL 트랜잭션 테스트 후 전부 rollback: direct grant/sequence 차단, 일반 회원 조회·검토 차단, 서비스 전용 접수, 원자적 알림·중복 접수, 변경된 동일 ID 충돌, 시간당 제한, NULL 필터, 메모 필수, revision 충돌, 요청·감사·제한표 TTL.
- 적용 후 실제 공개 REST의 관리자 목록 및 서버 전용 접수 직접 호출은 모두401/42501, 잘못된 Edge 입력은400. 신규 비회원 SECURITY DEFINER 실행 권한은 없다. Advisor의 private RLS/no-policy3개는 의도한 전면 차단이고, authenticated admin RPC2개는 서버 내부 관리자 검사로 제한한다. 기존 보안 경고는 이번 범위에서 변경하지 않았다.
- 전수 자동 검사:22,317개 각각 버튼·CSS·JS1개, 자신의 canonical 연결, 재생성 idempotence. 전체 검색4,619건 유지와 홈 보호 검사.
- PC1440: dialog600px·CTA44px, 모바일375/390/430 가로 넘침 없음·제출44px. 실제 iPhone/Samsung 기기 검사가 아닌 연결 브라우저 크기 에뮬레이션이다. 빈 입력 오류·닫기·Escape·포커스 복귀 확인.
- 최초 전체 검사403개 중401개 통과 후 관리 모듈 수 fixture와 배포 크기 문제를 수정. 반복 SVG 제거로 공개 공간 기준을 유지한다. 재생성 중 Windows 파일쓰기 오류에서 해당 후처리를 이어 실행했다. 후처리가 끝나기 전의 검사 결과는 완료 검사로 사용하지 않는다.

## 배포·운영 확인

현재 프런트엔드 GitHub/Pages 반영과 실제 테스트 접수·관리자 화면 확인을 진행 중이다. 이 문서의 앞선 자동 검사와 운영 브라우저 검증은 구분한다.

복구는 프런트엔드 기능 커밋을 되돌려 진입을 숨기는 방식으로 한다. 이미 접수된 데이터를 지우거나 기존 회원·원본 장소 데이터를 되돌릴 필요는 없다. DB/Edge는 비공개 접수 기록 보존 상태에서 별도로 판단한다. 사용자 미추적 `supabase/.temp/`, `tests/offline-shell.cjs`는 커밋하지 않는다.
